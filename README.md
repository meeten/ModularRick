## 🛠️ Архитектурный план и Техдолг (Roadmap)

### 🎯 Предстоящие задачи (Backlog)

#### 1. Обработка ошибок и Network Recovery
* **Цель:** Сделать приложение устойчивым к сбоям сети.

#### 2. Архитектурный рефакторинг
* **Цель:** Повысить поддерживаемость кода и подготовить проект к потенциальному расширению функционала.
* **Технические детали:**
  * Описать архитектурную карту (Architecture Map) с четким разделением зон ответственности (Data, Domain, Presentation).
  * Оптимизировать dependency injection (Dagger Hilt) для более гибкого тестирования.
  * Улучшить реактивные потоки данных (оптимизация работы со `StateFlow` / `SharedFlow`).

#### 3. Переход на Jetpack Paging 3
* **Цель:** Заменить самописную пагинацию на стандартное и оптимизированное решение от Google.
* **Технические детали:**
  * Реализация кастомного `PagingSource` для каскадной загрузки персонажей из API Rick and Morty.
  * Интеграция `Flow<PagingData<Character>>` во ViewModel и презентационный слой.
  * Использование `collectAsLazyPagingItems()` в Jetpack Compose для автоматического управления состоянием списков.

#### 4. Полноценный Offline Mode (Оффлайн-режим)
* **Цель:** Предоставить пользователю доступ к ранее загруженным персонажам без интернета.
* **Технические детали:**
  * Внедрение базы данных Room в качестве Single Source of Truth (Единого источника правды).
  * Использование библиотеки `RemoteMediator` (из Paging 3) для бесшовной синхронизации локального кэша БД и сетевых запросов при пагинации.
